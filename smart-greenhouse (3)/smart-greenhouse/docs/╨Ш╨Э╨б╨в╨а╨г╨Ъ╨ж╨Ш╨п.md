# Инструкция: что запустить самой

Всё, что можно проверить без внешних сервисов, уже выполнено в ноутбуке `notebooks/analysis.ipynb`. Здесь — то, что
нужно запустить на вашем компьютере: Jupyter, Docker-стек и виртуальные ESP32 в Wokwi. Делайте по порядку; после каждого
шага есть проверка «как понять, что получилось».

## 0. Подготовка (один раз)

1. Распакуйте `smart-greenhouse.zip` в папку без кириллицы и пробелов в пути, например `C:\projects\smart-greenhouse`
   или `~/projects/smart-greenhouse`.
2. Установите [Python 3.10+](https://www.python.org/downloads/) (на Windows поставьте галочку *Add Python to PATH*).
3. Установите [Docker Desktop](https://www.docker.com/products/docker-desktop/) и запустите его (значок кита в трее
   должен быть без ошибок). Проверка: в терминале `docker --version` и `docker compose version`.
4. Откройте терминал **в папке проекта** (Windows: PowerShell; в проводнике зайдите в папку, в адресной строке
   напишите `powershell` и Enter).

## 1. Ноутбук (5 минут)

```bash
pip install jupyter pandas numpy matplotlib scikit-learn scipy
pip install -r backend/requirements-dev.txt
jupyter notebook notebooks/analysis.ipynb
```

В Jupyter: **Kernel → Restart & Run All**. Выполнение занимает около минуты.
**Как понять, что получилось:** в части B видно «симуляция 72 ч выполнена», в части D — `OK` у тестов, в части F
(она заработает после второй команды pip) — статусы 200 и 202. Если часть D для прошивок пишет «g++/bash не найдены» —
это нормально на Windows, пропустите.

## 2. Docker-стек с симулятором узлов (10 минут)

Это самый простой способ увидеть всю систему «вживую», без Wokwi.

```bash
# Windows PowerShell:  copy .env.example .env
cp .env.example .env
```

Откройте `.env` в блокноте и замените значения `API_KEY`, `POSTGRES_PASSWORD`, `GRAFANA_PASSWORD` на свои
(`MQTT_HOST` оставьте `mosquitto`). Затем:

```bash
docker compose --profile sim up -d --build
docker compose ps
```

Первая сборка занимает несколько минут (скачиваются образы). **Как понять, что получилось:**

* `docker compose ps` показывает сервисы `mosquitto`, `timescaledb`, `backend`, `prometheus`, `grafana`, `simulator`
  в состоянии `running` (у некоторых `healthy`).
* http://localhost:8000/health отвечает `{"status":"ok"...}`.
* http://localhost:8000/ui — введите `API_KEY` из `.env`, через минуту появятся три узла со статусом `online`.
* http://localhost:3000 — логин `admin`, пароль `GRAFANA_PASSWORD`; **Dashboards → Greenhouse → «Умная теплица»**.
  Данные идут в реальном времени, подождите 3–5 минут, чтобы появились графики.
* API: `curl -H "X-API-Key: ВАШ_КЛЮЧ" http://localhost:8000/api/v1/devices`
  (в PowerShell пишите `curl.exe`, а не `curl`).

Полезные команды: `docker compose logs -f backend` (логи), `docker compose down` (остановить, данные сохранятся),
`docker compose down -v` (остановить и стереть данные).

## 3. Виртуальные ESP32 в Wokwi (30–40 минут)

Мы запускали узлы через VS Code (расширение Wokwi + PlatformIO): прошивка собирается командой `pio run`, а в
симуляторе подключается к локальному Mosquitto из Docker по адресу `host.wokwi.internal`. Публичный брокер
(`broker.hivemq.com`) на нашей сети рвал соединение каждые пару минут, поэтому его не используем.
Backend ходит в Mosquitto по имени `mosquitto` (`MQTT_HOST=mosquitto` в `.env`, ничего менять не надо).
Одновременно запускайте только один узел Wokwi и не включайте `--profile sim`: у симулятора те же device_id.

### 3.1. Уникальный префикс и перезапуск backend

```bash
docker compose down
python tools/set_topic_root.py my-team-42/greenhouse        # придумайте свой префикс: латиница, цифры, - и _
```

Затем направьте прошивки на локальный брокер и пересоберите их:

```bash
python tools/set_broker.py host.wokwi.internal
pio run -d firmware/gh-soil-01        # то же для gh-tank-01 и gh-climate-01
```

Backend запустите (**без** `--profile sim`, симулятор не нужен):

```bash
docker compose up -d --build
```

### 3.2. Три проекта в Wokwi

Повторите для каждого узла: `gh-soil-01`, `gh-tank-01`, `gh-climate-01` (папки в `firmware/`).

1. Откройте https://wokwi.com, войдите, **New Project → ESP32 → Arduino**.
2. В проекте уже есть вкладки `sketch.ino`, `diagram.json`. Замените их содержимое файлами из папки узла
   (откройте файл в блокноте, Ctrl+A, Ctrl+C, вставьте).
3. Добавьте ещё два файла: стрелка **▼** рядом с вкладками → **New file** → назовите `gh_common.h`, вставьте содержимое;
   так же `gh_logic.h`.
4. Библиотеки: вкладка `libraries.txt` (если её нет — создайте так же, как файлы) — вставьте содержимое
   из `libraries.txt` узла (`PubSubClient`, а для `gh-climate-01` ещё `ESP32Servo`).
5. Нажмите **▶**. В Serial Monitor должны появиться строки о подключении к Wi-Fi `Wokwi-GUEST`, брокеру и NTP.
6. Через несколько секунд узел появится в http://localhost:8000/ui как `online`.

### 3.2б. Вариант через VS Code (расширение Wokwi)

В папках `firmware/<узел>/` лежат `platformio.ini` и `wokwi.toml`, поэтому узлы можно собрать и запустить прямо в VS Code.

1. Установите расширения **PlatformIO IDE** и **Wokwi Simulator**. После PlatformIO перезапустите VS Code.
2. Откройте папку узла (File → Open Folder → `firmware\gh-soil-01`) в **отдельном окне** VS Code: одно окно запускает одну симуляцию.
3. Соберите: значок PlatformIO внизу (галочка «Build») или команда `pio run` в терминале. Первая сборка скачивает компилятор, это несколько минут.
4. Получите лицензию: F1 → **Wokwi: Request a new License** (бесплатная, нужен вход в браузере).
5. Запустите: F1 → **Wokwi: Start Simulator**. Окно симуляции покажет схему, Serial Monitor выводит лог.
6. Повторите для `gh-tank-01` и `gh-climate-01` в своих окнах.

### 3.3. Как «пошевелить» датчики

| Узел | Что нажать в Wokwi | Что должно произойти |
|---|---|---|
| `gh-soil-01` | ползунок влажности вниз (меньше 30 %) | включается насос (реле, светодиод), в UI — событие, влажность растёт |
| `gh-tank-01` | кликнуть HC-SR04 и увеличить расстояние (90 см и больше) | «бак критичен», зуммер, насос блокируется правилом backend |
| `gh-climate-01` | кликнуть NTC и поднять температуру выше 28 °C; фоторезистор — уменьшить освещённость | открывается форточка (сервопривод), включается досветка |

Для жары: если поднять температуру выше 35 °C, backend сам отправит `vent_open` и создаст событие `heat_alarm`.

## 4. Если что-то не работает

| Симптом | Что делать |
|---|---|
| `docker compose` не найден | запустите Docker Desktop и подождите, пока он загрузится; перезапустите терминал |
| порт 8000/3000/1883 занят | закройте программу, которая его использует, или поменяйте порт в `docker-compose.yml` |
| `backend` в статусе `restarting` | `docker compose logs backend`: чаще всего БД ещё стартует (подождите) или неверный пароль в `.env` (после смены пароля сделайте `docker compose down -v`) |
| в UI нет узлов (вариант А) | `docker compose logs simulator`; убедитесь, что запускали с `--profile sim` |
| в UI нет узлов (Wokwi) | **одинаковый** префикс в `.env` и в `gh_common.h`; после смены брокера или префикса обязательно `pio run` для всех узлов (старая сборка шлёт на старый адрес) и перезапуск симулятора Wokwi; не запускайте Wokwi вместе с `--profile sim` |
| Wokwi: ошибка компиляции «No such file» | проверьте, что созданы `gh_common.h`, `gh_logic.h` и заполнен `libraries.txt` |
| Wokwi: странные значения температуры | NTC в Wokwi задаётся параметрами; в Serial Monitor смотрите, что печатает узел, и сравнивайте с UI |
| Grafana пустая | подождите 3–5 минут; в правом верхнем углу выберите период «Last 15 minutes»; проверьте, что в UI есть данные |
| 401 в API | в заголовке `X-API-Key` должно быть значение `API_KEY` из `.env` |

Если ошибка не из таблицы, пришлите мне текст из `docker compose logs backend` или Serial Monitor — разберём.

## 7. Безопасность

* Не публикуйте `.env`; пароли и `API_KEY` должны быть своими.
* Публичный брокер доступен всем: не отправляйте через него ничего личного. Для настоящего применения включите пароль
  и TLS в `infra/mosquitto/mosquitto.conf`.
